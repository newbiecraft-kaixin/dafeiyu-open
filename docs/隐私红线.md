# 隐私红线与仓库卫生

> 起因：公开仓库 `dafeiyu-open` 的历史里长期留着管理员 QQ、本机路径和私密人设。
> 只改了工作区就以为没事，实际 `origin/main` 树和历史提交里都还在。
> 这份文档是以后每次提交前的检查清单，别再犯同样的傻。

## 一、铁律

1. **仓库是 PUBLIC，等于全世界可读。** 入库即公开，删掉当前文件不算删除，历史里还在。
2. **真实身份只留本地**：QQ 号、微信 ID、手机号、邮箱、`C:\Users\<用户名>` 这类绝对路径、`access.json`、dump 原文件。
3. **私密人设只留数据库**：病娇/亲密向人格的提示词放 `data_v4.db` 或 `services/hub/seeds/personas.local.json`（已被 `.gitignore` 忽略），**不要**写回 `services/hub/seeds/personas.json`。
4. **运行时产物不入库**：`config/migrate-journal.json`、`dump/`、`*.db`、`logs/`、表情缓存目录。
5. **文档里举例用占位符**：写「管理员账号」「主人 QQ」，不要写具体数字。

## 二、提交前自检（30 秒）

```powershell
# 1) 当前工作区有没有真实 ID / 本机路径
git grep -n -E "1[3-9][0-9]{9}|wxid_|Users[/\\\\][A-Za-z]"

# 2) 全历史有没有（关键：不能只看 HEAD）
git rev-list --all | git grep -I -n -E "1[3-9][0-9]{9}|wxid_|Users[/\\\\][A-Za-z]"

# 3) 确认仓库可见性和 fork 数（决定出事后的处理方式）
gh repo view <owner>/<repo> --json visibility,forkCount
```

第 2 条有命中，说明**历史已经脏了**，改工作区没用，必须走第三节。

## 三、历史已经脏了怎么办

破坏性操作，先备份再动手：

```powershell
# 0) 全量备份（放 TEMP，别放仓库里）
git bundle create "$env:TEMP\repo-before-rewrite.bundle" --all

# 1) 装工具（Windows 上 pip 装的 exe 通常不在 PATH，用绝对路径调）
python -m pip install git-filter-repo

# 2) 写替换规则 privacy-replace.txt（UTF-8）
#    <真实QQ>==><管理员QQ>
#    C:\Users\Someone==>%USERPROFILE%
#    regex:...（删整段敏感对象时用）

# 3) 重写（--force 是因为不是新 clone）
git-filter-repo --force --replace-text privacy-replace.txt \
  --path config/migrate-journal.json --invert-paths

# 4) filter-repo 会删掉 origin，重新加回来并恢复跟踪
git remote add origin <url>
git fetch origin
git branch --set-upstream-to=origin/main main

# 5) 强推（先确认真实远程 SHA 与本地记录一致，再 --force）
git ls-remote origin main
git push --force origin main

# 6) 用远程树再验一遍
git grep -n -E "<敏感串>" origin/main
```

注意：
- `--force-with-lease` 在旧对象已被 gc 掉时会报 `cannot parse expected object name`，此时先 `git ls-remote` 人工确认，再用 `--force`。
- 重写会改所有历史哈希，别人的旧 clone 必须重新 clone（0 fork 时影响可控）。
- 仓库 pack 会顺带瘦身（本次 607MB → 180MB）。

## 四、代码侧隐私边界（不要删）

- `check_master_activity`：群聊直接拒绝，只允许主人私聊查自己的记录。
- 合并转发进提示词前，剔除 `/`、`#`、`！` 开头的指令行——转发内容来自别人，不能当命令执行。
- 私聊通报主人失败时不要退回群里发，宁可只落日志。

## 五、比 grep 更狠的一招：拿 .gitignore 反查历史

`.gitignore` 里写着「不该入库」的文件，如果历史上曾经被提交过，就等于白写。
列出所有历史路径，再交给 `git check-ignore` 判定：

```powershell
git log --all --name-only --pretty=format: | Sort-Object -Unique |
  Where-Object { $_ } | Set-Content "$env:TEMP\hist_paths.txt"
Get-Content "$env:TEMP\hist_paths.txt" | git check-ignore --stdin -v
```

命中即「现在是忽略的、但历史里存在」，用 `--invert-paths` 整条路径删掉。

本次实测被这条命令抓出来的：

| 路径 | 里面是什么 |
| --- | --- |
| `zz_prompt_dump/dump/*.json` | 主人私聊 + 多个群的全量对话，含真实 QQ |
| `data/local_tools/access.json` | 管理员/成员的权限与身份 |
| `data/local_tools/workspace/*.png` | local_exec 的桌面截屏 |
| `data/stickers/_src_data.json` | 表情来源与发送者 ID |

注意两点：
- `filter-repo` 会 `reset --hard`，**工作区里的这些文件会被直接删掉**。要留本地就先拷出去，或事后再从备份 bundle 里 `git archive` 取回。
- `git log -S<字符串>` 只搜**文件内容**，搜不到文件名里的 QQ 号；文件名也要单独查。

## 六、API Key / 会话凭据

- 真实 key 只放 `data/cmd_config.json`（不在入库白名单里），插件 `config.json` 里留空或占位。
- 扫描口径：`sk-`、`sk-ant-`、`AIza`、`ghp_`、`AKIA`、`-----BEGIN ... PRIVATE KEY-----`、`SESSDATA=`、`bili_jct=`、`Authorization: Bearer`。
- 本次全历史扫描结论：命中项全是上游文档里的占位符（`xxx`、`your-key`、`***`），**没有真实密钥**。
- 即便如此，只要历史上出现过真实 cookie/key，删除文件不等于作废，**必须去平台重置**。
